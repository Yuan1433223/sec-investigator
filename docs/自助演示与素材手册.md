## 可选本地运行

在项目根目录执行；运行说明以 [README](../README.md#本地运行可选) 为准。

```powershell
uv sync
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

配置与 `LLM_PROVIDER` 匹配的 key、端点和模型。模板默认 anthropic；使用 OpenAI 兼容服务时也要改 provider。保持 `DATA_SOURCE=fake`，不需企业 VPN、ES 或 Prometheus 实例。不配置飞书 webhook 即不发送飞书消息。

```powershell
cd web
npm ci
npm run build
cd ..
$env:DATA_SOURCE = "fake"
$env:FEISHU_ALERT_WEBHOOK_URL = ""
uv run sec-investigator
```

打开 <http://localhost:18230>。改前端后重新 build 并刷新。不要为演示强制结束未知进程；若端口占用，确认占用进程后处理。

## 一条足够的演示路径

选用现有源站 5xx 故障样例，突出下列过程：

1. 输入目标，展示解析后的资产和进入的阶段。
2. 展开一项工具观测，解释“模型选择查询，工具返回数值”。
3. 展示分项风险，说明支持的关键指标由代码抽取、风险按策略计算。
4. 出现 critical 审核时说明“继续生成报告需要人工确认”。
5. 展示结构化报告，区分观测证据、根因假设与人工执行的建议。

没有自动封禁、重启或修复。不要使用“批准后自动处置”的解说；也不要把所有阶段描述为并行执行。

## 截图与视频

建议 1440×900 或 1920×1080 桌面截图：调查全景、工具观测详情、人工审核、最终报告。准备一段 60—90 秒视频即可；可剪去等待，但说明经过剪辑，不伪造未完成的调查结果。

解说围绕业务问题、执行过程和工程边界，不逐行朗读节点名。图中显示的执行摘要不代表模型私有思维链。作者在公开展示前确认素材中的业务标识和个人贡献说明。

## 演示边界

已修复工具资源隔离、报告结构化风险、并发工具结果关联和审批拒绝状态。fake 模式下连通性工具明确返回“未检测”，不会主动 ping 样例目标。

模型可能选择不同工具或生成不同解释，报告正文仍须结合原始证据检查；一次冒烟不能证明诊断准确率，也不代表 real 模式已联调。
