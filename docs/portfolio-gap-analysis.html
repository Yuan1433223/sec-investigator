② HITL 审批门是死路径

审批触发条件是存在 risk_level==critical 的 finding，而 critical 判定依赖 LLM 在 finding 里填原始数字字段（rate_5xx / rate_4xx / cpu_pct）。实跑中 LLM 把这些字段写成 prose 甚至空 dict（incident1 error_rate={}），deterministic classifier 拿不到数 → 一律默认 low → 永不 critical → approval_gate 永不 interrupt。审批弹窗两次实跑零触发。AGENTS.md 最想展示的"约束自治 / 人在回路"卖点，demo 里演不出来。

_tool_tracing.py:166 → investigation.py:84 → sse.py:43 → useInvestigation.ts:53

工具事件由 create_react_agent 内部子图里的 _tool_tracing.py:166 get_stream_writer() 写出； 但 surfaces/api/investigation.py:84 用顶层 graph.astream(..., stream_mode="custom")， 子图 custom 事件默认不冒泡到父图流（未开 subgraphs=True 或未在 worker 节点重发）。 surfaces/web/sse.py:43 正确映射了 ToolCallEvent，前端 useInvestigation.ts:53 也处理 tool_call——中间断在父子图事件冒泡。 结果：UI 时间线只有 node status，"逐步展示代理每一步动作"名不副实。

4.2 三条格局判断

平台层

已被占住

告警聚合 + 工作流 + Web console：Keep / Argus / ASP / Robusta，都在往"AI 关联"加能力。不要再做一个大而全 SOC 平台。

调查层

仅 AiSOC 完整

agent 真正去查证据、给 verdict：开源里最完整的是 AiSOC；SRE 侧 HolmesGPT/AURA 工程更成熟但不碰安全语义。

大厂层

闭源留窗口

MS MDASH 私有预览、Google/Wiz/Elastic 无对应开源 agentic SOC 调查器；大厂只放 runtime 治理工具。空位=窄而深的垂直 agent。

4.3 个人项目差异化结论

不要做又一个大 SOC 平台。选一个别人不做的纵深——国内 WAF / 高防 / CC-DDoS + ES/Prom 并行取证就是差异化；叠加三个叙事资产：可离线一键复现（fake/real seam 已踩在正确方向）、可审计性（Investigation Ledger / 证据引用 / OTel，安全场景下"能不能复盘每一步"比"准不准"先被客户问）、MCP 化（让 Claude/飞书/ASP 反过来调你，比自建入口省力）。Keep 可作上游而非竞品。

5.1 五个"该抄的范式"

① Dify

节点状态灯 + 节点日志抽屉

运行时画布每个节点亮灯：灰=pending、蓝=running、绿=success、红=error，节点下方展开输入/输出/耗时日志。
映射：现有 PipelineRail 升级为横向 stepper，每个 LangGraph 节点一颗状态灯，running 节点 1.5s 呼吸光晕，点击节点过滤/展开该节点事件抽屉。

② OpenHands

多资产事件泳道

左栏垂直事件流，每条带时间戳+可折叠参数，思考链默认折叠一行。
映射：EventLog 升级为按资产分组的泳道——dispatch_machine_checks / dispatch_security_checks 扇出的 N 个 worker 各一条竖轨，工具调用以 Step 卡 append。这是 sec-investigator 区别于单 agent demo 的核心视觉卖点。

③ Langfuse

可折叠 trace span 树 + 右侧 JSON 抽屉

左侧 span 树嵌套缩进，右侧 span 详情（输入/输出 JSON、token、延迟、错误堆栈），上方 waterfalls 时间条。
映射：工具调用痕迹做成 span 树：supervisor → machine_check(asset A) → ES 查询 → 命中证据；右侧抽屉看原始请求/响应。这是"安全调查可信度"的视觉载体。

④ CopilotKit / AG-UI

Step 折叠卡 + 事件分类

工具调用自动渲染成 Step Card：左图标+工具名+状态点（spinner→check）+右侧耗时，点开 mono 入参/出参。
映射：直接照抄事件分类作为后端 SSE schema；Step 卡视觉就是工具调用卡模板。外加 LangGraph Studio 范式：approval_gate 触发时在事件轨插入内联审批卡（风险摘要+受影响资产+批准/驳回），批准即 Command(resume=true)。

⑤ Vercel ai-chatbot

artifact 侧栏流式报告

左聊天、右 artifact 面板，报告边推理边流式渲染，可切 markdown 预览/源码，完成后可导出。
映射：ReportCard 升级为独立 artifact 面板：reporter 执行时 markdown 报告在右侧实时流式渲染（react-markdown+remark-gfm+shiki），完成后给"导出 MD/PDF"按钮——收尾画面。

7.1 前端选型结论

主干：Tailwind CSS + shadcn/ui 自研（React19+Vite6 原地升级）。 不选 Chainlit（布局被框架锁死，与"前端独立 Vite+FastAPI"方向相反）； 不选 CopilotKit 当外壳（产品形态是 copilot 侧栏，套上去控制台一眼"又一个 copilot demo"，损失作品集辨识度）； assistant-ui 仅用于可选 supervisor 对话切片（Thread/Composer copy 到自己仓库）。 CopilotKit 的 AG-UI 事件分类和 Step 卡视觉是免费教科书，必须抄。

7.4 后端 P0 修复方向（不写代码，写要点）

P0

reporter structured output 稳定性

schema 解析失败时重试/换更强模型；降级路径不应是常态。当前两次实跑都走降级，说明 report_writer profile 与 schema 不匹配。

P0

critical 判定直接吃工具产出的结构化数字

不要依赖 LLM 在 finding 里转述 rate_5xx/rate_4xx/cpu_pct——worker 工具查询结果本身就是结构化数字，deterministic classifier 直接读工具输出，LLM 只做叙事。这是审批门能触发的前提。

P0

修 fixture 数值自洽

incident2 5xx 改回与 incidents.md 一致的 ~63%，或反过来改叙事——二选一，消除 62.9% vs 22.9% 矛盾。

P0

修子图事件冒泡

父图 astream 开 subgraphs=True，或在 worker 节点里把 ToolCallEvent 重发到父图 custom stream——让 UI 时间线有工具调用。

09演示脚本建议

30 秒版

一句话抓住

点 incident2（api2.xs2027.cn）→ 看流水线状态灯转、多资产泳道并行 append 工具调用 → critical 触发审批卡 → 点批准 → 右侧 markdown 报告流式出。三句话收尾："约束自治——critical 才停人审；证据可回放——每步工具调用都在；一键离线复现——fake 数据源无需 VPN。"
